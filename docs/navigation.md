# Navigation (Nav2 + SLAM + RealSense)

Stack choice (Kobuki TurtleBot2 + RPLIDAR A1 + Intel RealSense):

| Job | Choice | Why |
|---|---|---|
| 2D SLAM (default) | **slam_toolbox** (online async) | Nav2's default partner in Jazzy, light enough for a Pi/Jetson, good loop closure |
| 2D SLAM (alternative) | cartographer_ros (`slam:=cartographer`) | Optional; heavier, less maintained |
| 3D / RGB-D SLAM | **RTAB-Map** (`slam:=rtabmap`) | Uses the RealSense; optional |
| Localization on a saved map | **AMCL** + map_server | Standard Nav2 |
| Planner / controller | NavFn + **Regulated Pure Pursuit** behind a rotation shim | Much lighter than the stock MPPI |
| Velocity safety | Nav2 collision_monitor, then **`cmd_vel_mux_node`** | The mux clamps and applies a watchdog to everything that moves the robot |

Frames follow the Kobuki driver: `map -> odom -> base` (**`base`**, not `base_link`), lidar frame `laser`.

## !!! Measure these before trusting any map or localization
`param/navigation.yaml` holds the static transforms `base -> laser` and `base -> camera_link`.
**The values are placeholders** (lidar 0.25 m up, camera 0.10 m forward / 0.30 m up). Measure the
real mounting from the `base` origin (x forward, y left, z up, yaw radians) and edit them. Also
check `robot_radius` (0.18 m is a guess) in `param/nav2_params.yaml`.

## Run it on the robot
```
export PATH=/usr/bin:$PATH; source env.sh                              # system Python first
ros2 launch kobuki_node kobuki_node-launch.py                          # from ~/ros2_ws: odom -> base, commands/velocity
ros2 launch framework_bringup sensors.launch.py                        # RPLIDAR (sllidar_ros2) + RealSense
ros2 launch framework_bringup extensions.launch.py cmd_vel_topic:=commands/velocity \
    enable_arm:=false enable_pose:=false enable_social:=false          # mux -> Kobuki, nav_extension
```
1. **Map** (drive with teleop or the BT, then save):
   `ros2 launch framework_bringup navigation.launch.py slam:=slam_toolbox`
   Save with the BT node `SaveMap file="room1"` (writes `~/maps/room1.yaml/.pgm`, never overwrites
   unless `overwrite="true"`) or `ros2 run nav2_map_server map_saver_cli -f ~/maps/room1`.
2. **Navigate on the map**:
   `ros2 launch framework_bringup navigation.launch.py map:=$HOME/maps/room1.yaml`
   Give AMCL the starting pose: `initial_pose:=x,y,yaw`, rviz "2D Pose Estimate", or the BT node
   `SetInitialPose`.
3. **Go somewhere** from a behaviour tree (`ros2 run bt_orchestrator submit_bt tree.xml --run`):
   `NavigateToPose x y [yaw frame timeout_ms]`, `NavigateToPlace place` (names in
   `param/places.yaml`, which the LLM is told about), `IsNearPose x y [tolerance]`,
   `ClearCostmaps`. Halting the tree cancels the Nav2 goal.

`cmd_vel_topic:=commands/velocity` is the Kobuki input; the driver stops after 0.6 s without
commands, and the mux stops publishing (one zero Twist) 0.5 s after its last input.

Depth: `sensors.launch.py depth_scan:=true` publishes `/depth_scan` (depthimage_to_laserscan); add
`depth_scan` to `observation_sources` of both costmaps in `param/nav2_params.yaml` to use it.
RTAB-Map reads the RealSense color + aligned depth (`param/realsense.yaml` enables alignment).

## Try it without a robot: nav_sim
`nav_sim` ray-casts a simulated RPLIDAR on a map and integrates `cmd_vel` into odometry
(emulating the Kobuki's 0.6 s command timeout), so the real Nav2/AMCL/slam_toolbox can be tested:
```
ros2 launch framework_bringup nav_sim.launch.py                # AMCL on maps/test_room.yaml
ros2 launch framework_bringup extensions.launch.py enable_arm:=false enable_pose:=false \
    enable_odom:=false enable_pid:=false enable_social:=false  # mux + nav_extension
ros2 launch framework_bringup nav_sim.launch.py slam:=slam_toolbox   # mapping in the sim
```
`maps/test_room.yaml` (12 x 8 m, two rooms and a door) is generated by `ros2 run nav_sim make_test_map`.
`maps/my_map.yaml` is a copy of `~/maps/my_map.yaml`; it is a patchy partial scan whose connected
free space is only about 2.6 m^2 for a 0.18 m robot, so Nav2 cannot plan long routes on it.

## Verified vs not
**Verified in simulation** (nav_sim + the real Nav2/AMCL/slam_toolbox/Cartographer nodes, goals sent
through the BT path: `submit_bt` -> bt_validator -> bt_executor -> nav_extension -> Nav2 -> cmd_vel_mux
-> simulated robot; ROS domain 41, no hardware):

| Check | Result |
|---|---|
| `NavigateToPlace right_room` on `test_room`, through the door (~11 m) | BT `SUCCESS` after ~48 s, `IsNearPose` 0.14 m from the goal, AMCL error 0.065 m |
| AMCL started 0.5 m / 0.25 rad off, 3-leg route (left room, door, right room) | all legs arrived; error 0.034 m on the first leg, 0.063 m at the end |
| BT halted mid-route | executor `HALTED`, Nav2 goal cancelled (bt_navigator "Goal canceled"), `nav2/cmd_vel` stopped, mux output went to zero 0.04 s later, robot moved 0.000 m in the next 3 s |
| Mux clamp on Nav2's output (limit set to 0.12 m/s while Nav2 asked 0.25) | mux output peaked at exactly 0.120 m/s |
| Mux watchdog: `collision_monitor` killed with SIGKILL mid-drive | mux held the last command 0.48 s, then one zero Twist, then silence; robot at rest |
| slam_toolbox, 5 % odometry heading drift, 5 BT legs + `SaveMap` | all `SUCCESS`; pose error 0.072 m; saved map: 99.9 % of free cells truly free, 95.8 % of occupied cells within 1 cell of a wall, 100 % of true walls recovered |
| Cartographer (`param/cartographer/kobuki_2d.lua`), same drift, 4 legs + `SaveMap` | all `SUCCESS`; pose error 0.054 m; map 99.8 % / 99.9 % / 99.4 % |
| `SaveMap` BT node | wrote `<map_dir>/<file>.yaml/.pgm`; refuses names with `/`, `..` and existing files unless `overwrite="true"` |
| RTAB-Map launch, depth_scan node, `sensors.launch.py` logic | start without parameter errors (RTAB-Map then waits for the camera); sensors.launch.py evaluated offline: every argument exists in `rs_launch.py` / `sllidar_a1_launch.py` |
| Unit tests | 28 new Python tests (map ray casting, kinematics, places/map-name/result logic) + the existing suite (140 pass) |

**Failed / limitation:** on `~/maps/my_map.yaml` AMCL localizes (0 m error at the start pose) but
Nav2 **cannot plan** a 3 m route ("Failed to create plan"): that saved map is a patchy partial scan
whose connected free space is only ~2.6 m^2 for a 0.18 m robot. The BT correctly reported
failure (no hang). Re-map the room (slam_toolbox) and use that map.

**NOT verified (needs the robot):** the Kobuki driver, the RPLIDAR via `sllidar_ros2`, the
RealSense stream, RTAB-Map actually mapping (no RGB-D data was available), depth obstacles in the
costmaps, Nav2 tuning on the real robot (speeds, footprint, inflation), CPU load on a Pi/Jetson,
real sensor noise and wheel slip (the simulator's lidar is nearly ideal, odometry only has a
heading scale error). The base->laser / base->camera_link transforms are **placeholders**.
